Genome graph indexing

gfaidx

Fast, on-demand access to the parts of a GFA genome graph that matter.

View gfaidx on GitHub

gfaidx indexes genome graphs so a query can retrieve a subgraph quickly and efficiently, without first loading the complete graph into memory.

Index once. Query any region.

Instead of treating a large GFA as one file that must be loaded all at once, gfaidx keeps it in queryable indexed chunks. A request reads only the relevant graph neighborhood.

Interactive graph visualization

The WebAssembly frontend is being developed in the graphviz_wasm repository, and the backend is part of the MMseqs2 app API. This lets the visualizer request a subgraph for any query, then render the returned result on demand.

Try the live graph visualizer

Open the graph you need

The gfaidx API is also being implemented in BandageNG. It will make it possible to open an indexed graph and visualize a requested subgraph immediately in BandageNG, rather than overwhelming memory by loading the complete graph, which is Bandage's current default behavior. This will allow users to explore HPRC-sized graphs effortlessly using BandageNG or BandageJS, or to send API requests directly from their own apps.

Help shape these tools

gfaidx and its integrations are under active development. Feedback from people using the tools is very welcome.

The BandageJS frontend currently includes only a couple of example graphs. After the server is migrated to fast NVMe storage, HPRC version 2 graphs will be available there as fully indexed graphs for visualization and API requests.
